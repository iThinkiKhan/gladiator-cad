# ESP32-CAM / C6 bench results — 2026-10-13

Jim authorized flashing both boards. The ESP32-CAM was flashed over its CH340 USB adapter; the XIAO ESP32C6 was updated through its existing authenticated OTA path. The C6 native serial interface was bound to an Android ADB driver on the bench PC; no Windows drivers were changed.

| Check | Result |
|---|---|
| CAM board | ESP32-D0WD-V3 revision 3.1; OV2640; PSRAM detected |
| USB programming | Bootloader, partition table, and app writes verified by esptool |
| Initial sensor problem | Probe returned 0x105 / ESP_ERR_NOT_FOUND; sensor detected after Jim unplugged power and checked/reseated the ribbon |
| Video image | Actual 320×240 JPEG inspected; no captured image published |
| Sustained video | 1,343 complete JPEG frames in 90.02 seconds, 14.92 fps |
| Status during video | 28 sample sets; zero status request failures |
| Gateway polling during steady video | CAM pollErrors remained 0 |
| PSRAM under video | Constant 4,083,275 bytes free |
| CAM free heap under video | Sampled 148,932–165,176 bytes |
| C6 API latency under video | Median status 78 ms; visual snapshot 63 ms |
| C6 errors during steady video | Frame error counter remained 0 |
| C6 interruption/recovery | Same verified C6 image applied while video ran; camera frame counter preserved, Wi-Fi rejoined, new JPEG obtained afterward |
| Camera address persistence | C6 camera-address setting survived its reboot |
| Display API authorization | Missing maintenance key rejected with HTTP 401 |
| Missing S3 state | Offline expression, null sensor values; a temporary greeting could not conceal absent telemetry |
| Physical TFT | Jim confirmed the ST7789 is not connected yet; only graphics-buffer allocation verified |
| S3 state/sensor effects | Not tested: no live S3 telemetry at this bench |

This is a 90-second camera test, not a 30-minute event endurance run. The display loop ran concurrently, but the SPI screen was physically absent. Reconnect testing intentionally produced temporary polling failures while C6 updated/rebooted; the camera recovered. Stream-error increments also occur when a viewer closes its socket and should not be interpreted alone as sensor failures.

The C6 serves the field interface at its standard AP address, with an opt-in camera panel. The camera is an AP client; reserve its DHCP address and configure it in Camera setup. Direct video requires the operator to reach the camera's subnet. Keep one video viewer at a time.
